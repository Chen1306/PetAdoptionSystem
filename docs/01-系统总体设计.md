# 流浪动物管理及领养系统总体设计

## 1. 项目目标

流浪动物管理及领养系统用于解决线下救助与领养流程不透明、宠物信息分散、审核效率低的问题。系统面向两类角色：

- 普通用户：注册登录、浏览宠物、提交领养申请、查看申请进度、维护个人信息。
- 管理员：管理用户、管理宠物、审核宠物信息、审核领养申请、查看统计数据。

## 2. 技术选型

- 前端：Vue 2、Element UI、Axios、Vue Router
- 后端：Spring Boot 2.7.x、MyBatis、Maven
- 数据库：MySQL 5.7 / 8.0
- 认证方式：Token
- 接口风格：RESTful API + JSON

## 3. 系统架构

系统采用前后端分离架构：

1. 前端负责页面渲染、表单校验、路由控制、权限菜单展示。
2. 后端负责认证授权、业务处理、数据校验、日志记录、数据库访问。
3. 数据库负责用户、宠物、领养申请等业务数据持久化。

### 3.1 分层设计

- 表现层：Vue 页面、组件、路由、状态管理
- 接口层：Controller，对外暴露 REST 接口
- 业务层：Service，封装业务规则与事务
- 持久层：Mapper + XML，完成数据库 CRUD
- 数据层：MySQL 表、索引、约束

### 3.2 角色权限模型

- 游客：仅可查看宠物列表与宠物详情
- 普通用户：游客权限 + 提交申请 + 查看个人中心 + 查看申请记录
- 管理员：拥有全部后台功能

## 4. 核心业务流程

### 4.1 用户领养流程

1. 用户注册并登录系统
2. 浏览已审核通过且可领养的宠物
3. 查看宠物详情并提交领养申请
4. 系统生成待审核申请
5. 管理员审核申请
6. 用户查看申请结果

### 4.2 宠物发布与审核流程

1. 管理员录入宠物信息
2. 宠物初始状态为未审核
3. 管理员审核宠物信息
4. 审核通过后前台可见
5. 若宠物已被领养，则不可再次被申请

### 4.3 用户状态管理流程

1. 管理员查看用户列表
2. 可启用或禁用普通用户账号
3. 被禁用用户不可登录，也不可发起领养申请

## 5. 功能模块划分

### 5.1 前台模块

- 用户注册
- 用户登录 / 退出
- 宠物列表
- 宠物详情
- 领养申请
- 我的申请
- 个人中心

### 5.2 后台模块

- 管理员登录
- 用户管理
- 宠物管理
- 宠物审核
- 领养申请审核
- 数据统计
- 操作日志

## 6. 状态设计

### 6.1 用户状态

- ENABLED：启用
- DISABLED：禁用

### 6.2 宠物审核状态

- PENDING：待审核
- APPROVED：审核通过
- REJECTED：驳回

### 6.3 宠物领养状态

- AVAILABLE：可领养
- ADOPTED：已领养

### 6.4 领养申请状态

- WAITING：待审核
- PASSED：已通过
- REJECTED：已拒绝
- CANCELED：用户已取消

## 7. 关键业务规则

1. 同一用户对同一只宠物只能存在一条有效申请记录。
2. 仅待审核状态的申请允许用户取消。
3. 已领养宠物不可再次发起申请。
4. 只有宠物审核通过后，普通用户才能在前台看到。
5. 管理员审核领养申请通过后，应同步更新宠物领养状态为已领养。
6. 禁用用户不能登录、不能申请领养。
7. 登录、审核、删除等关键操作需要记录日志。

## 8. 非功能设计要求

- 安全性：基于角色权限控制接口访问
- 可维护性：状态字段、宠物类型可扩展
- 可用性：页面结构清晰，表单提示友好
- 可移植性：支持 Windows 开发环境
- 可扩展性：后续可增加宠物图片管理、领养回访、公告模块
