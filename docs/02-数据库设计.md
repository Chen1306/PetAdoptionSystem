# 流浪动物管理及领养系统数据库设计

## 1. 设计说明

基于需求文档，原始数据词典只有 `users`、`pet`、`adopt` 三张核心表。为了保证后续开发可落地、字段可扩展，本设计在三张核心业务表基础上补充了通用字段，并建议增加一张操作日志表。

## 2. 表清单

- `users`：用户表
- `pets`：宠物表
- `adopt_records`：领养申请表
- `operation_logs`：操作日志表，建议新增

## 3. 表结构设计

### 3.1 users 用户表

| 字段名 | 类型 | 主键 | 非空 | 默认值 | 说明 |
| --- | --- | --- | --- | --- | --- |
| id | bigint | 是 | 是 | 自增 | 用户ID |
| username | varchar(50) | 否 | 是 |  | 用户名，唯一 |
| password | varchar(100) | 否 | 是 |  | 密码，建议加密存储 |
| phone | varchar(20) | 否 | 是 |  | 手机号 |
| role | varchar(20) | 否 | 是 | user | 角色：user/admin |
| status | varchar(20) | 否 | 是 | ENABLED | 用户状态 |
| created_at | datetime | 否 | 是 | CURRENT_TIMESTAMP | 创建时间 |
| updated_at | datetime | 否 | 是 | CURRENT_TIMESTAMP | 更新时间 |

约束建议：

- `username` 唯一
- `phone` 可唯一
- `role` 取值限制为 `user/admin`

### 3.2 pets 宠物表

| 字段名 | 类型 | 主键 | 非空 | 默认值 | 说明 |
| --- | --- | --- | --- | --- | --- |
| id | bigint | 是 | 是 | 自增 | 宠物ID |
| pet_name | varchar(50) | 否 | 是 |  | 宠物名称 |
| type | varchar(20) | 否 | 是 | other | 宠物类型：cat/dog/other |
| age | int | 否 | 是 | 0 | 年龄 |
| gender | varchar(20) | 否 | 否 | unknown | 性别 |
| image_url | varchar(255) | 否 | 否 |  | 图片路径 |
| description | varchar(500) | 否 | 否 |  | 宠物描述 |
| review_status | varchar(20) | 否 | 是 | PENDING | 审核状态 |
| adopt_status | varchar(20) | 否 | 是 | AVAILABLE | 领养状态 |
| reviewer_id | bigint | 否 | 否 |  | 审核人 |
| review_remark | varchar(255) | 否 | 否 |  | 审核意见 |
| reviewed_at | datetime | 否 | 否 |  | 审核时间 |
| created_at | datetime | 否 | 是 | CURRENT_TIMESTAMP | 创建时间 |
| updated_at | datetime | 否 | 是 | CURRENT_TIMESTAMP | 更新时间 |

约束建议：

- `age >= 0`
- `type` 取值限制为 `cat/dog/other`
- 前台仅展示 `review_status=APPROVED and adopt_status=AVAILABLE`

### 3.3 adopt_records 领养申请表

| 字段名 | 类型 | 主键 | 非空 | 默认值 | 说明 |
| --- | --- | --- | --- | --- | --- |
| id | bigint | 是 | 是 | 自增 | 申请ID |
| user_id | bigint | 否 | 是 |  | 申请用户ID |
| pet_id | bigint | 否 | 是 |  | 宠物ID |
| apply_description | varchar(500) | 否 | 是 |  | 申请说明 |
| status | varchar(20) | 否 | 是 | WAITING | 申请状态 |
| audit_remark | varchar(255) | 否 | 否 |  | 审核意见 |
| audited_by | bigint | 否 | 否 |  | 审核管理员ID |
| audited_at | datetime | 否 | 否 |  | 审核时间 |
| created_at | datetime | 否 | 是 | CURRENT_TIMESTAMP | 创建时间 |
| updated_at | datetime | 否 | 是 | CURRENT_TIMESTAMP | 更新时间 |

约束建议：

- 外键：`user_id -> users.id`
- 外键：`pet_id -> pets.id`
- 唯一业务约束：同一用户对同一宠物只能存在一条有效申请

实现建议：

- 可以通过唯一索引 `uk_user_pet(user_id, pet_id)` 实现
- 若需要保留取消后的再次申请能力，可改为程序校验 + 逻辑约束

| created_at | datetime | 否 | 是 | CURRENT_TIMESTAMP | 创建时间 |

## 4. 表关系说明

- 一个用户可以提交多个领养申请
- 一只宠物可以对应多个历史申请，但同一时刻只能有一个通过申请
- 一个管理员可以审核多个宠物和多个领养申请

关系图可抽象为：

- `users 1 -> n adopt_records`
- `pets 1 -> n adopt_records`
- `users 1 -> n operation_logs`

## 5. 索引设计建议

### users

- `uk_users_username(username)`
- `idx_users_role(role)`
- `idx_users_status(status)`

### pets

- `idx_pets_review_status(review_status)`
- `idx_pets_adopt_status(adopt_status)`
- `idx_pets_type(type)`

### adopt_records

- `idx_adopt_user_id(user_id)`
- `idx_adopt_pet_id(pet_id)`
- `idx_adopt_status(status)`
- `uk_adopt_user_pet(user_id, pet_id)`

## 6. 建表 SQL 草案

```sql
CREATE TABLE users (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    username VARCHAR(50) NOT NULL UNIQUE,
    password VARCHAR(100) NOT NULL,
    phone VARCHAR(20) NOT NULL,
    role VARCHAR(20) NOT NULL DEFAULT 'user',
    status VARCHAR(20) NOT NULL DEFAULT 'ENABLED',
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);

CREATE TABLE pets (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    pet_name VARCHAR(50) NOT NULL,
    type VARCHAR(20) NOT NULL DEFAULT 'other',
    age INT NOT NULL DEFAULT 0,
    gender VARCHAR(20) DEFAULT 'unknown',
    image_url VARCHAR(255),
    description VARCHAR(500),
    review_status VARCHAR(20) NOT NULL DEFAULT 'PENDING',
    adopt_status VARCHAR(20) NOT NULL DEFAULT 'AVAILABLE',
    reviewer_id BIGINT,
    review_remark VARCHAR(255),
    reviewed_at DATETIME,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);

CREATE TABLE adopt_records (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    user_id BIGINT NOT NULL,
    pet_id BIGINT NOT NULL,
    apply_description VARCHAR(500) NOT NULL,
    status VARCHAR(20) NOT NULL DEFAULT 'WAITING',
    audit_remark VARCHAR(255),
    audited_by BIGINT,
    audited_at DATETIME,
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    CONSTRAINT fk_adopt_user FOREIGN KEY (user_id) REFERENCES users(id),
    CONSTRAINT fk_adopt_pet FOREIGN KEY (pet_id) REFERENCES pets(id)
);

CREATE TABLE operation_logs (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    operator_id BIGINT,
    operator_role VARCHAR(20),
    module VARCHAR(50) NOT NULL,
    action VARCHAR(50) NOT NULL,
    target_id BIGINT,
    content VARCHAR(500),
    ip VARCHAR(50),
    created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
);
```

## 7. 设计结论

数据库层建议不要完全照搬原始三张表的最简字段，而是保留：

- 状态分离：宠物审核状态与领养状态分开
- 审核留痕：申请审核意见、审核人、审核时间
- 通用时间字段：便于排序、统计、审计
- 用户状态字段：支持管理员禁用用户

这样可以明显降低后续开发时的结构性返工。
