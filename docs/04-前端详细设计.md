# 流浪动物管理及领养系统前端详细设计



## 1. 设计目标

前端采用 `Vue 2 + Element UI + Axios + Vue Router`，目标是完成两套使用场景：

- 前台：普通用户浏览宠物、提交领养申请、查看申请记录、维护个人信息
- 后台：管理员管理用户、宠物、领养申请，并查看统计数据

本设计强调三点：

1. 页面结构简单清晰，适合课程设计快速开发
2. 与当前 Spring Boot 后端接口一一对应，便于联调
3. 前后台共用同一前端项目，通过路由和角色区分页面

## 2. 技术方案

- 框架：Vue 2
- UI：Element UI
- 路由：Vue Router
- 请求：Axios
- 状态管理：本项目建议先使用 `localStorage + 全局工具模块`
- 构建工具：Vue CLI

说明：

- 当前项目体量不大，可以先不引入 Vuex，减少复杂度
- 登录用户信息、token、角色信息先保存在 `localStorage`
- 若后续页面增多，再升级为 Vuex 或 Pinia 替代方案

## 4. 页面架构设计

## 4.1 前台页面

### 4.1.1 登录页

路径：`/login`

用途：

- 普通用户和管理员共用登录入口
- 登录成功后根据角色跳转

页面元素：

- Logo / 系统名称
- 用户名输入框
- 密码输入框
- 登录按钮
- 注册跳转按钮

交互规则：

- 表单校验通过后调用 `POST /api/auth/login`
- 登录成功后保存 `token`、`userId`、`username`、`role`
- `role=user` 跳转 `/pets`
- `role=admin` 跳转 `/admin`

### 4.1.2 注册页

路径：`/register`

页面元素：

- 用户名
- 手机号
- 密码
- 确认密码
- 注册按钮

交互规则：

- 前端先校验两次密码一致
- 调用 `POST /api/auth/register`
- 注册成功后跳转登录页

### 4.1.3 宠物列表页

路径：`/pets`

布局建议：

- 顶部为导航栏
- 中部为搜索筛选区
- 下方为卡片式宠物列表

页面元素：

- 顶部导航：系统名、宠物列表、我的申请、个人中心、退出登录
- 搜索框：按名称模糊搜索
- 类型下拉框：`cat / dog / other`
- 查询按钮、重置按钮
- 宠物卡片列表

卡片信息：

- 图片
- 名称
- 类型
- 年龄
- 性别
- 简介
- 查看详情按钮

交互规则：

- 进入页面自动请求 `GET /api/pets`
- 搜索条件变化后重新请求列表
- 若未登录，也允许访问此页面

### 4.1.4 宠物详情页

路径：`/pets/:id`

布局建议：

- 左侧图片展示
- 右侧基本信息和操作按钮
- 下方描述区

页面元素：

- 宠物图片
- 名称、类型、年龄、性别
- 描述
- 申请领养按钮

交互规则：

- 进入页面调用 `GET /api/pets/{id}`
- 未登录点击“申请领养”时跳转登录页
- 普通用户点击“申请领养”打开申请弹窗
- 管理员不展示申请按钮

### 4.1.5 领养申请弹窗

建议作为通用组件：

- 组件名：`AdoptionDialog.vue`

页面元素：

- 宠物名称展示
- 申请说明输入框
- 提交按钮

交互规则：

- 调用 `POST /api/adoptions`
- 成功后提示提交成功
- 可选择跳转“我的申请”

### 4.1.6 我的申请页

路径：`/my-adoptions`

页面元素：

- 申请列表表格
- 宠物ID
- 申请说明
- 申请状态
- 创建时间
- 操作列

状态展示建议：

- `WAITING`：黄色标签
- `PASSED`：绿色标签
- `REJECTED`：红色标签
- `CANCELED`：灰色标签

操作规则：

- 仅 `WAITING` 状态显示“取消申请”按钮
- 点击后调用 `PUT /api/adoptions/{id}/cancel`

### 4.1.7 个人中心页

路径：`/profile`

页面元素：

- 用户基本信息卡片
- 编辑资料表单
- 保存按钮

交互规则：

- 页面加载调用 `GET /api/users/profile`
- 修改后调用 `PUT /api/users/profile`

- 类型
- 年龄

## 5. 路由设计

```text
/login
/register
/pets
/pets/:id
/my-adoptions
/profile
/admin
/admin/users
/admin/pets
/admin/adoptions
```

### 5.1 路由权限规则

- 游客可访问：
  - `/login`
  - `/register`
  - `/pets`
  - `/pets/:id`

- 普通用户可访问：
  - `/my-adoptions`
  - `/profile`

- 管理员可访问：
  - `/admin`
  - `/admin/users`
  - `/admin/pets`
  - `/admin/adoptions`

### 5.2 路由守卫设计

在 `router.beforeEach` 中处理：

1. 读取 `token` 和 `role`
2. 若目标页面需要登录但没有 token，跳转 `/login`
3. 若普通用户访问后台路由，跳转 `/pets`
4. 若管理员访问普通用户功能页，可跳转 `/admin`

## 6. 接口封装设计

## 6.1 request.js

职责：

- 配置 `baseURL=http://localhost:8080`
- 统一添加 `Authorization`
- 统一处理错误提示
- 响应中只返回后端 `data`

请求拦截器：

- 从 `localStorage` 中读取 `token`
- 若存在则添加到请求头

响应拦截器：

- `code=200` 直接返回
- `code=401` 清空登录状态并跳转登录页
- 其余错误统一 `Message.error`

## 7. 状态与本地缓存设计

本地缓存建议统一使用以下 key：

- `PET_ADOPT_TOKEN`
- `PET_ADOPT_USER`
- `PET_ADOPT_ROLE`

保存内容：

```json
{
  "userId": 1,
  "username": "admin",
  "role": "admin"
}
```

退出登录时清空全部缓存。

## 9. UI 风格建议

课程设计场景下，建议采用简洁、稳定、容易实现的风格：

- 主色：绿色或橙色，贴合“宠物领养 / 救助”主题
- 卡片圆角：8px
- 页面背景：浅灰色
- 内容区：白色卡片
- 按钮风格：主按钮突出，危险操作使用红色

前台视觉重点：

- 宠物图片展示
- 卡片式信息布局
- 空状态友好提示

后台视觉重点：

- 表格清晰
- 操作按钮集中
- 状态标签颜色明确

## 12. 设计结论

前端整体建议采用“单项目、双场景”的设计方式：

- 前台负责用户浏览和申请
- 后台负责管理和审核
- 通过 `token + role + 路由守卫` 完成权限隔离

按照这份设计继续开发时，可以直接开始：

1. 搭建 Vue2 工程
2. 配置 Axios 和路由
3. 先完成登录页和宠物列表页
4. 再逐步补齐后台页面
