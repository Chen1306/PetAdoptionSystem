# 密码加密设计

## 1. 设计目标

用户密码不以明文形式存入数据库。注册和修改密码时，对原始密码计算 MD5 后存储；登录时对输入的原始密码做相同计算，与数据库中的哈希值比较。

## 2. 方案说明

- 算法：MD5
- 存储格式：32 位小写十六进制字符串
- 存储字段：沿用 `users.password`，`VARCHAR(100)` 足够
- 是否加盐：不加盐
- 传输方式：前端仍提交原始密码，生产环境必须通过 HTTPS 传输，服务端负责哈希

### 取舍说明

MD5 计算速度快、实现简单，适合课程设计和演示场景。但它不加盐，且已被证明不适合密码存储：

- 相同密码得到相同哈希值
- 常见密码可通过彩虹表反查
- GPU 暴力破解速度快

生产环境应使用 BCrypt、Argon2id 等自适应慢哈希算法。

## 3. 处理流程

### 3.1 注册

1. 前端提交原始密码
2. 后端校验参数
3. 计算 `MD5(rawPassword)`
4. 将哈希值写入 `users.password`

### 3.2 登录

1. 前端提交原始密码
2. 按用户名查询用户
3. 计算 `MD5(rawPassword)`
4. 与数据库中的 `password` 比较，一致则登录成功

### 3.3 修改密码

1. 前端提交新密码
2. 计算 `MD5(newPassword)`
3. 更新 `users.password`

## 4. 代码实现

| 文件 | 作用 |
| --- | --- |
| `src/main/java/com/petadopt/util/PasswordUtil.java` | 提供 MD5 工具方法 |
| `src/main/java/com/petadopt/service/impl/AuthServiceImpl.java` | 注册写入哈希、登录校验哈希 |
| `src/main/java/com/petadopt/service/impl/UserServiceImpl.java` | 修改密码写入哈希 |
| `sql/pet_adopt_init.sql` | 初始化用户的密码改为哈希值 |

核心方法：

```java
public static String md5(String rawPassword) {
    return DigestUtils.md5DigestAsHex(rawPassword.getBytes(StandardCharsets.UTF_8));
}
```

## 5. 数据迁移

### 5.1 重新初始化数据库

重新执行 `sql/pet_adopt_init.sql` 即可，种子用户密码已替换为哈希值：

| 用户名 | 原始密码 | 数据库存储值 |
| --- | --- | --- |
| admin | admin123 | 0192023a7bbd73250516f069df18b500 |
| user01 | 123456 | e10adc3949ba59abbe56e057f20f883e |
| user02 | 123456 | e10adc3949ba59abbe56e057f20f883e |

### 5.2 保留现有数据

如果数据库已有明文密码且不想重建，执行一次：

```sql
UPDATE users SET password = MD5(password);
```

注意：该语句只能执行一次。重复执行会变成二次哈希，导致所有用户无法登录。

## 6. 验证标准

1. 注册新用户后查询 `users.password`，应为 32 位小写十六进制字符串，不是明文。
2. 使用注册时的原始密码可以登录，错误密码登录失败。
3. 修改密码后旧密码失效，新密码可以登录。
4. 后端执行 `mvn -DskipTests compile` 编译通过。

## 7. 后续升级建议

如需提升安全性，可将 `PasswordUtil` 替换为 BCrypt：

- `SecurityConfig` 中已存在 `BCryptPasswordEncoder` bean，可直接注入使用
- 注册和修改密码时调用 `encode(rawPassword)`
- 登录时调用 `matches(rawPassword, storedHash)`
- 从 MD5 升级到 BCrypt 时，已有密码无法直接转换，需要用户重新设置密码，或在登录成功时逐步升级为 BCrypt 哈希
